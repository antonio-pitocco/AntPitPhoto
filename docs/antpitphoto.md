# AntPitPhoto

AntPitPhoto is AntPitLab's build of [LightCraft](https://github.com/storytold/lightcraft)
(MIT OR Apache-2.0), tuned for preparing fine-art exhibition prints and their web versions.
It is an independent fork: not affiliated with or endorsed by the LightCraft or ArtCraft authors.

*AntPitPhoto è la versione di LightCraft di AntPitLab, pensata per preparare stampe fine-art da
mostra e le loro versioni web.*

## What it adds to LightCraft

- **Italian interface** (`crates/ui-egui/locales/it.json`, `it-formats.json`; Edit ▸ Language ▸
  Italiano). The app built by `packaging/macos/antpitphoto-local.sh` starts in Italian.
- **«Mostra» export presets** (File ▸ Export with Preset):
  - lab print, TIFF 16-bit Adobe RGB, 300 ppi, full resolution, matte-paper sharpening;
  - the same for baryta paper (glossy sharpening);
  - 40×60 cm print with a 5 cm paper border (6 cm at the bottom);
  - web gallery, JPEG sRGB 2560 px, quality 85, 4:4:4, screen sharpening, no GPS.
- **Print size in centimetres** — `printCm` in `app.export`: a number (long edge in cm) or
  `[width, height]` in cm (the photo fits the box in either orientation), at the export `ppi`.
  It is an exact size: it upsamples when needed.
- **Printed paper border / mat** — `border`: centimetres on every side, or
  `{cm, bottomCm?, gray?}` (heavier bottom border; `gray` 0–255, 255 = paper white). It is added
  after sharpening and watermark, outside the picture; the picture keeps the size asked for.
- **No hidden cap on headless print exports**: without a size, `lightcraft-cli run … app.export`
  used to write 3000 px even for a 16-bit TIFF at 300 ppi (a 25 cm print instead of 80). 16-bit
  TIFF/PSD, files with `ppi` or with a border now export at full resolution.
- **Name and icon**: the macOS app is `AntPitPhoto.app` (bundle id `it.antpitlab.antpitphoto`)
  with its own icon (`assets/app-icon/antpitphoto/`, regenerated by
  `packaging/macos/antpitphoto-icons.sh`): a print with its exhibition mat, in the 3:2 frame,
  where the shadows glow amber and the light dissolves into lavender.

- **The camera's look on the raw** — `profile.fromCamera` (Develop: *Match Camera JPEG*): the open raw gets a
  profile fitted to its own camera JPEG, so it starts from the film simulation (Classic Neg, Eterna, Acros…), the
  Sony Creative Look or the picture style chosen in camera, and every edit still works on the raw. A 17³ 3D LUT
  takes the photo's default rendering to the JPEG (least squares on 256 px renders of the central 90 %, with a
  smoothness penalty and a weak pull towards the identity for colours the photo does not contain); it is kept
  only when it brings held-out pixels closer, saved in the library's `Profiles/` and listed under
  «Come in macchina» with Amount 0–200 %. Measured on the 240 px "look" scale (mean ΔE76 against the camera JPEG,
  central 80 %): RX10 V with FL, 3.9–5.3 → 1.0–1.7 at 24, 103 and 600 mm; X100VI with Eterna, 4.5 → 1.9; a table
  fitted on one FL photo brings another from 4.1 to 1.9. The film simulation is not read from the metadata yet:
  the command is run on a photo of that look.
- **Lens corrections for AntPitLab's bodies**: Sony A7C and RX10 V tables (see
  [sony-lens-corrections.md](sony-lens-corrections.md)); other lenses, e.g. Canon EF-S, from a lensfun database
  copied into `~/Library/Application Support/LightCraft/lensfun` ([lens-profiles.md](lens-profiles.md)).
- **AI denoise download** offered in Settings ▸ AI Denoise: the build enables `rawnind-model`, so RawNIND's
  Bayer model can be fetched. Its weights are GPL-3.0: they are downloaded to the Mac at the user's request and
  are not part of the app or of this repository (no permissively licensed model exists for the network the
  denoiser runs; see [denoise.md](denoise.md)). Using them privately has no obligations; passing the model file on
  falls under the GPL. Fuji X-Trans raws are not denoised yet: the engine runs the
  Bayer model only.
- **Printer profile on export** — `printProfile` (path of an RGB printer + paper ICC profile) and
  `printIntent` (`perceptual`, default, or `relative`) in `app.export`: the JPEG, PNG or TIFF (8 or
  16 bit) is converted into the printer's space and tagged with its profile, ready for a home
  print with the driver's colour management off. Soft proof first with the same profile (View ▸
  Soft Proof). Paper border, if any, is converted too (paper white stays paper white).
- **Toning** (Color Grading panel, `toning.sepia`, `toning.selenium`, `toning.strength`): a
  darkroom toner, not a split tone. Sepia acts on the lights first and reaches the shadows as it
  grows (bleach-and-redevelop); selenium acts on the shadows first and deepens the blacks
  (Dmax). Both together give a double-toned print. Strength scales both.
- **Curves inside masks** (`mask.curve {id?, channel?: master|red|green|blue, points}`, Masking
  panel ▸ Mask Curve): a point curve that acts only inside the mask, blended by its coverage —
  dodging and burning with a grade per zone (hard contrast in the shadows, soft in the sky).
- **One-click people masks** (Masking panel: Person, Skin, Hair, Clothing): SAM 3 concept prompts
  (`person`; `face, neck, hand`; `hair`; `clothing, coat, jacket, dress, trousers, hat`). From a script:
  `mask.add {"kind": "prompt", "text": "person"}`. They need the SAM 3 model ([ai-masks.md](ai-masks.md)).
- **Content-aware fill that keeps thin structures**: `spot.add {mode: "fill"}` decides the hole
  in structure order (exemplar-based inpainting, Criminisi–Pérez–Toyama 2004) before the
  patch-based completion, so a pole, a cable or a horizon crossing the spot is continued.
- **Faithful preview without exporting** — `develop.renderPreview {path, size?}`: the active photo
  through the export pipeline (every mask and matte at full quality) at `size` px on the long
  edge, unlike a screenshot taken while finer masks are still being computed.
- **Commands bound to a photo** — every command accepts `photo` (an id): when it is not the active
  photo the command fails and changes nothing (a script never edits the wrong photo because a
  selection did not happen).
- **Mask geometry is taken as given or refused**: misspelt keys, malformed points, a linear mask
  whose start equals its end, a radial mask without size are errors, not silent defaults.
- **Export results say what happened to existing files**: `replaced: true` when a file was
  overwritten, `renamedFrom` when a free name (`-2`) was used instead.

Libraries, presets and settings stay LightCraft's: AntPitPhoto opens the same libraries.

## Build and install (macOS, Apple silicon)

```sh
export CARGO_TARGET_DIR=/a/disk/with/space/lightcraft-target   # the build needs ~15 GB
bash packaging/macos/antpitphoto-local.sh        # build, ad-hoc sign, install in /Applications
bash packaging/macos/antpitphoto-local.sh --skip-build --no-install   # package only
```

The app is signed ad hoc for the Mac that builds it; other Macs' Gatekeeper refuses it.

## Examples

```sh
# TIFF for the lab, 40×60 cm at 300 ppi, 5 cm border (6 at the bottom)
antpitphoto-cli run --library LIB app.export '{"ids":[1],"preset":"Mostra: stampa 40×60 cm con bordo carta 5 cm (TIFF 16 bit Adobe RGB, 300 ppi)","dir":"OUT"}'
# Lightroom presets (.xmp) are imported as they are, colour grading included
antpitphoto-cli run --library LIB preset.import '{"paths":["PRESETS/MyLook"]}'
```

## Known limits (from LightCraft)

- No Print module (page layout, printer dialog): print proofs go through the export with
  `printProfile`, then the printer driver with its colour management off; CMYK printer profiles
  and black-point compensation are not available.
- The border is not drawn in the preview: it is only in the exported file.
